# UI/UX 레퍼런스

## 주 레퍼런스 지정

이 프로젝트의 가상 모바일뱅킹 화면·기본 송금 흐름은 **신한 SOL뱅크 공식 체험 서비스 '돈 보내기'**를 주 레퍼런스로 사용한다.

- URL: https://nsol.shinhan.com/contents/guide/step05__send-money/index.html (sources.md 참고)
- 적용 원칙:
  - 송금 화면의 기본 정보 구조·단계 흐름·입력 방식·버튼 배치 방식은 신한 SOL 공식 체험을 적극 참고한다.
  - 실제 사용자가 모바일뱅킹을 연습하는 느낌이 들 정도로 기본 사용 흐름은 유사하게 설계한다.
  - 다만 신한은행 로고·명칭·브랜드 색상·이미지·아이콘·화면 디자인은 그대로 복제하지 않는다.
  - 서비스 내부 은행은 특정 실제 은행이 아닌 가상의 은행으로 만든다.
  - 필요하면 다른 은행의 공통적인 UX도 보완 참고한다.

## 송금 기본 흐름

SPEC F4 기준 6단계: 이체 → 은행 선택 → 계좌번호 → 금액 → 확인 → 완료.

아래 "신한 SOL뱅크 참고 포인트"에서 확인했듯, 실제 신한 SOL 흐름은 이 6단계와 정확히 일치하지 않는다 (인증·메모 단계 존재). 자세한 비교는 "SPEC과의 비교"절 참고.

## 신한 SOL뱅크 참고 포인트

신한 SOL뱅크 공식 체험 페이지(`nsol.shinhan.com/contents/guide/step05__send-money/`)를 처음부터 끝까지 직접 확인한 결과다. 이 사이트는 실제 앱이 아니라 스크린샷 기반의 "따라하기 체험" 가이드 페이지로, 각 화면(01.html~08.html)이 실제 앱 화면 캡처 이미지와 안내 문구로 구성되어 있다.

### 1. 시작 화면

- 소개 화면(index.html)에 메인 비주얼과 함께 "버튼 몇 번 누르면 손 쉽고 안전하게 돈을 보낼 수 있어요" 문구, [시작하기] 버튼이 있다.

### 2. 송금 진입 방식

- [시작하기] 클릭 → 01.html 안내 화면 → "손주에게 용돈 보내기를 따라해 보세요"라는 구체적 시나리오 제시 → 다음(02.html)으로 진입.
- 진입 자체가 실제 은행 앱 홈 화면에서 "이체/송금" 메뉴를 누르는 동작이라기보다, 가이드 사이트의 안내 문구를 거쳐 첫 실제 화면으로 넘어가는 구조다.

### 3. 받는 계좌 입력 방식 (02.html)

- 화면 문구: "손주의 신한은행 계좌로 용돈을 보내 보세요" / "110-123-123456 계좌를 입력해 주세요" (예시 계좌번호가 이미 화면에 제시됨)
- 계좌번호 입력 필드 + 전용 숫자 키패드(`keypad--number.png`)
- 은행 선택은 별도 화면이 아니라 **계좌번호 입력 화면 안의 바텀시트**(`bs_select-bank.png`)로 처리된다.
- 계좌번호 확인도 별도 바텀시트(`bs_confirm-account-number.png`)로 뜬다.

### 4. 금액 입력 방식 (03.html)

- 화면 문구: "50,000원을 입력해 주세요"
- 금액 전용 숫자 키패드(`keypad--money.png`), "원" 단위 표시.

### 5. 확인/인증 방식 (04~05.html)

- 04.html: "6자리 비밀번호를 입력해 주세요" — 비밀번호 전용 키패드(`keypad--password.png`)와 마스킹 처리(`digit-*.png`)로 6자리 인증을 받는다. **이 인증 단계는 현재 SPEC F4의 6단계(이체→은행선택→계좌번호→금액→확인→완료)에는 없다.** → `[SPEC 반영 검토 필요]`
- 05.html: 이체 확인/완료로 추정되는 화면(이미지 `step05/5.png`). 페이지 HTML에는 반복되는 안내 문구만 있고 이 화면 고유의 문구는 스크린샷 이미지 안에 있어 텍스트로는 확인되지 않았다. `[원문 재확인 필요]` (스크린샷을 직접 열어 확인 필요).

### 6. 송금 완료 방식 (06~08.html)

- 06.html: "돈 보낸 후에 메모를 하실 수 있어요" — 송금 완료 후 **메모 입력 옵션**을 제안한다.
- 07.html: "메모를 입력할 수 있어요" — 메모 입력 화면.
- 08.html: "입력하신 메모를 확인 하실 수 있어요" + **"따라하기 미션을 성공하셨습니다!"** — 메모 확인과 함께 체험 자체의 완료(미션 성공) 메시지가 함께 표시된다.
- **메모 입력(06~07단계)은 현재 SPEC에 없는 기능이다.** → `[SPEC 반영 검토 필요]`

### 7. 숫자 키패드 구성

- 입력 종류별로 다른 키패드 이미지를 쓰는 것으로 확인된다: 계좌번호용(`keypad--number.png`), 금액용(`keypad--money.png`), 비밀번호용(`keypad--password.png`).
- 키패드가 스크린샷 이미지이므로 버튼 배치(숫자 순서, 지우기/확인 버튼 위치 등) 세부 사항은 텍스트만으로 확인되지 않는다. `[원문 재확인 필요]` (이미지 직접 열람 필요).

### 8. 취소/이전/처음으로 돌아가기 방식

- 모든 화면 공통: 우측 상단의 원형 버튼(닫기/X)을 누르면 진행 상태와 무관하게 **즉시 첫 화면(index.html)으로 이동**한다.
- 단계별 "한 단계 뒤로" 전용 버튼이 있는지는 텍스트로 명확히 확인되지 않았다. `[원문 재확인 필요]`
- 사이트 전체에 "모든 화면들은 따라하기 체험으로 실제 가입, 거래가 되지 않아요"라는 안내가 공통으로 표시된다.

### 9. 화면별 주요 문구 (원문)

| 화면 | 문구 |
|---|---|
| 시작 | "버튼 몇 번 누르면 손 쉽고 안전하게 돈을 보낼 수 있어요" |
| 안내(01) | "손주에게 용돈 보내기를 따라해 보세요" |
| 계좌 입력(02) | "손주의 신한은행 계좌로 용돈을 보내 보세요" / "110-123-123456 계좌를 입력해 주세요" |
| 금액 입력(03) | "50,000원을 입력해 주세요" |
| 인증(04) | "6자리 비밀번호를 입력해 주세요." |
| 메모 제안(06) | "돈 보낸 후에 메모를 하실 수 있어요" |

| 공통 | "모든 화면들은 따라하기 체험으로 실제 가입, 거래가 되지 않아요" |

### 10. 고령자가 이해하기 쉬운 요소 / 어려울 수 있는 요소

**이해하기 쉬운 요소**
- "손주에게 용돈 보내기"처럼 구체적이고 익숙한 생활 시나리오를 제시한다.
- 각 화면마다 "무엇을 입력해야 하는지"를 문장으로 안내한다(예: "50,000원을 입력해 주세요").
- 입력 종류(계좌/금액/비밀번호)마다 전용 키패드를 따로 둔다.

**어려울 수 있는 요소**
- 6자리 비밀번호 인증 단계 — 별도 설명 없이 갑자기 등장하면 "왜 비밀번호를 또 입력해야 하는지" 혼란을 줄 수 있다.
- 계좌번호가 미리 채워진 예시 형식("110-123-123456")으로 제시되어, 실제 입력 동작 자체를 체험하는 것인지 값을 그대로 두는 것인지 헷갈릴 수 있다.
- 메모 입력 단계 — 송금 완료 후 선택적으로 등장하는 추가 단계라 "송금이 이미 끝난 것인지" 헷갈릴 수 있다.

## SPEC과의 비교

`SPEC.md` F4(송금 6단계: 이체→은행선택→계좌번호→금액→확인→완료)와 실제 신한 SOL 흐름을 비교한다. SPEC 내용은 이번 조사로 임의 변경하지 않았다.

| 항목 | 신한 SOL | 현재 금융한걸음(SPEC) | 반영 여부 |
|---|---|---|---|
| 진입 | 가이드 안내 화면을 거쳐 첫 화면 진입 | F3 가상 홈 화면에서 이체 버튼으로 진입 | 반영 |
| 은행 선택 | 계좌번호 입력 화면 안 바텀시트로 통합(별도 화면 아님) | SPEC F4는 "은행 선택"을 계좌번호 입력 **앞의 별도 단계**로 명시 | 팀 결정 필요 (바텀시트 통합 vs 별도 화면 유지) |
| 계좌번호 입력 | 전용 숫자 키패드 + 예시 계좌 프리필 | F4 계좌번호 단계 + F5(Should) 대형 키패드 | 반영 |
| 금액 입력 | 전용 숫자 키패드 + "원" 단위 | F4 금액 단계 + F5(Should) 키패드 | 반영 |
| 비밀번호 인증(6자리) | 04.html에 별도 인증 단계 존재 | SPEC 6단계에 인증 단계 없음(계좌·금액 다음 바로 확인) | `[SPEC 반영 검토 필요]` |
| 확인 화면 | 05.html 이체 확인/완료 추정(문구 미확인) | F4 "확인" 단계 존재 | 반영 |
| 메모 입력 | 06~07.html에서 선택적 메모 입력 제안 | SPEC 어디에도 메모 기능 없음(Must/Should/Could 전부 미포함) | `[SPEC 반영 검토 필요]` (또는 제외) |
| 완료/성공 화면 | "따라하기 미션을 성공하셨습니다!" (08.html) | F15 미션 완료 화면 | 반영 (성공 메시지 컨셉 유사) |
| 취소/처음으로 | 전 화면 공통 우상단 X 버튼 → 즉시 처음 화면 | SPEC에 취소/이전 버튼 관련 명시 없음 | `[SPEC 반영 검토 필요]` |

## 여러 은행에서 공통적으로 참고할 요소

`[실사용 확인 필요]` — 신한 SOL 외 다른 은행 앱의 공통 패턴은 아직 조사 전이다. 특정 은행 하나가 아니라 여러 은행 앱의 송금 흐름에서 공통적으로 나타나는 패턴을 확인한 뒤 정리한다.

## 고령자 친화 UI 원칙

- 큰 글씨
- 큰 버튼
- 충분한 버튼 간격
- 한 화면에 과도한 정보 금지
- 실제 금융용어가 필요하면 쉬운 설명 병기 고려 (SPEC F2, Could)

## 금융한걸음 적용 원칙

- 신한 SOL뱅크 '돈 보내기'를 기본 정보 구조·단계 흐름·입력 방식의 주 레퍼런스로 삼되, 로고·명칭·브랜드 색상·이미지·아이콘·화면 디자인은 그대로 복제하지 않는다.
- 서비스 내부 은행은 특정 실제 은행이 아닌 **가상의 은행**으로 만든다.
- 필요하면 다른 은행의 공통적인 UX도 보완 참고한다.
- 교육용 가상 화면이며 실제 송금이 아니라는 사실이 화면에서 분명해야 한다.

## 구현 시 주의사항

- SPEC 11.2 담당표 기준, UI 관련 파일(`bank-ui.html`, `styles.css`)은 A 담당이며 `mission-engine.js`, `ai-guide.js`는 건드리지 않는다.
- SPEC 7절에 따라 F5(대형 키패드)는 Should다. Must 범위에서는 계좌번호·금액 입력에 기본 `<input>` 하나가 F4 화면 안에 반드시 포함되어야 한다.
- SPEC 5.2에 따라 마이크 권한은 보안 컨텍스트(localhost 또는 https)를 요구할 수 있다. `file://`로 직접 열면 마이크가 막힐 수 있으므로 UI 담당도 이 제약을 인지하고 시연 방식을 맞춰야 한다.
