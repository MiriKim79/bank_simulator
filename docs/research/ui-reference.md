# UI/UX 레퍼런스

## 주 레퍼런스 지정

이 프로젝트의 가상 모바일뱅킹 화면·기본 송금 흐름은 **신한 SOL뱅크 공식 체험 서비스 '돈 보내기'**를 주 레퍼런스로 사용한다.

- URL: https://nsol.shinhan.com/contents/guide/step05__send-money/index.html (sources.md 참고)
- 적용 원칙:
  - 송금 화면의 기본 정보 구조·단계 흐름·입력 방식·버튼 배치 방식은 신한 SOL 공식 체험을 적극 참고한다.
  - 실제 사용자가 모바일뱅킹을 연습하는 느낌이 들 정도로 기본 사용 흐름은 유사하게 설계한다.
  - 다만 신한은행 로고·명칭·브랜드 색상·이미지·아이콘·화면 디자인은 그대로 복제하지 않는다.
  - 서비스 내부 은행은 특정 실제 은행이 아닌 가상의 은행으로 만든다.
  - 필요하면 다른 은행의 공통적인 UX도 보완 참고한다.

## 송금 기본 흐름

SPEC F4 기준 6단계: 이체 → 은행 선택 → 계좌번호 → 금액 → 확인 → 완료.

아래 "신한 SOL뱅크 참고 포인트"에서 확인했듯, 실제 신한 SOL 흐름은 이 6단계와 정확히 일치하지 않는다 (인증·메모 단계 존재). 자세한 비교는 "SPEC과의 비교"절 참고.

## 신한 SOL뱅크 참고 포인트

SPEC.md 13.1~13.2 기준(2026-08-19, **브라우저로 8화면 직접 확인**). 이 절의 이전 버전은 화면이 전부 PNG 스크린샷이라 텍스트만 긁어 조사했고, 그 결과 아래 두 가지를 잘못 적었었다. SPEC 13.5에서 브라우저 직접 확인으로 정정되었으므로 이 문서도 그 정정 내용으로 갱신한다.

> **정정 1**: 이전에는 "진행 표시(1/3 등)가 텍스트로 확인되지 않는다"고 적었으나, 실제로는 화면 제목 오른쪽에 `1 / 3` `2 / 3` `3 / 3` 배지가 **존재한다.**
> **정정 2**: 이전에는 "04 화면 = 6자리 비밀번호 입력 단계"라고 적었으나 **틀렸다.** 실제로 SOL의 "쉬운이체" 모드는 비밀번호를 받지 않고 확인 모달의 `이체하기` 버튼 하나로 바로 완료된다(툴팁: "이체가 바로 완료됩니다.").

| 항목 | 내용 |

### 실제 SOL 송금 흐름 (SPEC 13.2, 8화면 직접 확인)

모든 화면 공통: 앱바(왼쪽 뒤로가기 + 화면 이름, 오른쪽 아이콘 3개 — 홈에서는 `챗봇`·`음성`·`마이` **글자 라벨까지 붙는다**), 화면 맨 아래 고정 문구 "따라하기 체험화면으로 실제 이체가 되지 않아요", 캐릭터 말풍선 + 빨간 점 `Click Here`로 다음 누를 곳을 안내.

| # | 화면 | 핵심 내용 |
|---|---|---|
| 01 | 쉬운 홈 | 계좌카드(잔액 623,540원) + `돈보내기`·`간편앱출금` 버튼. 아래 2열 큰 타일 4개(`전체계좌조회`·`돈보내기`·`상품가입`·`ATM 돈찾기`). 진입점이 카드와 타일 두 곳 |
| 02 | 받는통장 입력 `1 / 3` | 은행명 선택 + 계좌입력. 바텀시트로 `최근`·`내계좌`·`직접입력` 탭 + 은행 로고 그리드 |
| 03 | 보내는통장, 금액 입력 `2 / 3` | 출금계좌 카드(잔액 998,800원) + 금액 입력. `다음` 버튼은 **입력 전 비활성(회색)**. 금액 칩(`1만`·`5만`·`10만`·`100만`·`전액`) + 숫자 키패드(하단에서 슬라이드업) |
| 04 | 입력사항 확인 `3 / 3` | 받는사람·계좌·금액(가장 큰 글씨)·"이체할까요?" + 확인 모달(`취소`/`이체하기`) + **"이체가 바로 완료됩니다." — 비밀번호를 받지 않는다** |
| 05 | 이체완료 | 헤더 색이 파랑→초록으로 전환. 영수증(거래일시·받는통장·금액·메모) |
| 06 | 거래내역조회 | 계좌 잔액이 998,800→948,800으로 감소. 거래 1건 표시 |
| 07 | 거래내역상세(모달) | 메모입력(최대 20자), 거래구분·거래 후 잔액 등 상세 |
| 08 | 미션 성공 | "따라하기 미션을 성공하셨습니다! 다음 따라하기를 이어해 주세요!" + 버튼 3개(`한번 더 따라하기`/`처음으로 이동하기`/`ATM 돈 찾기 따라하기`) |

SOL의 입력 단계는 **3개**(받는통장 / 보내는통장·금액 / 확인)이고 완료는 세지 않는다. 우리 흐름(SPEC 4.1 F4+F15): `home → bank → account → amount → confirm → done`.

### 화면별 주요 문구 (SPEC 13.2 원문)

| 화면 | 문구 |
|---|---|
| 02 받는통장 입력 | 진행 배지 `1 / 3` |
| 03 금액 입력 | 진행 배지 `2 / 3`, `다음` 버튼 입력 전 비활성 |
| 04 확인 | 진행 배지 `3 / 3`, "이체할까요?", 확인 모달 "이체가 바로 완료됩니다." |
| 08 완료 | "따라하기 미션을 성공하셨습니다! 다음 따라하기를 이어해 주세요!" |
| 공통 | "따라하기 체험화면으로 실제 이체가 되지 않아요" |

### 고령자가 이해하기 쉬운 요소 / 어려울 수 있는 요소

**이해하기 쉬운 요소**
- 짧은 존댓말 질문형 문구("~을 입력해 주세요" 형태의 화면 제목)
- 확인/완료 화면에서 금액만 가장 큰 글씨로 강조
- 도움 진입점(챗봇·음성)이 앱바에 항상 있고, 홈에서는 아이콘에 글자 라벨까지 붙는다

**어려울 수 있는 요소 / 우리가 직접 설계해야 하는 부분**
- **SOL 체험에는 오답·예외 화면이 아예 없다** (SPEC 13.4). 빨간 점이 찍어주는 곳만 누르게 되어 있어 사용자가 틀릴 수가 없는 구조다. 즉 **오답 피드백(F8)은 SOL에서 베낄 대상이 없고, 이 서비스가 직접 설계해야 하는 부분**이며 SOL 체험과 명확히 구별되는 지점이다.
- `다음` 버튼이 입력 전에는 비활성인 SOL 방식과 달리, 금융한걸음은 버튼을 항상 활성 상태로 두고 눌러서 틀려보는 것을 학습 방식으로 삼는다(SPEC 13.3 R10) — 의도된 차이이지 실수가 아니다.

## 금융한걸음과 비교 (SPEC 13.3 분류)

SPEC 13.3에서 SOL 흐름과 SPEC이 다른 곳을 **반영 / 단순화 / 제외 / 팀 결정 필요**로 분류한 내용이다. 이 문서는 SPEC 13.3을 요약해 옮긴 것이며, 등급·값 변경은 SPEC 원문과 팀 결정을 따른다.

### 반영 — SOL 방식이 맞고 우리도 그렇게 되어 있다(또는 근거가 보강됐다)

| 항목 | 내용 |
|---|---|
| 홈에서 송금 시작 | 앱을 열면 계좌 화면이고 거기서 이체를 누른다 — F3 → `transfer`로 이미 일치 |
| 진행 표시 | SOL도 실제로 `1/3` 등 배지를 쓴다 — F17의 근거가 "학습용 장치"에서 "실제 앱 관행"으로 보강됨 |
| 큰 금액 표시 | 확인·완료 화면에서 금액만 가장 큰 글씨로 강조 — 이미 일치 |
| 도움 진입점 | 앱바에 챗봇·음성 아이콘이 상시 있고 홈에서는 글자 라벨까지 붙음 — F14 배치 근거 |
| 완료 후 다시 연습 | SOL 08의 "한번 더 따라하기" — F15의 `restart`와 이미 일치 |
| 실제 송금이 아닌 연습 화면 표시 | SOL 전체에 "실제 거래가 되지 않아요" 고정 문구 — 이미 일치 |

### 단순화 — SOL과 다르게 가되 학습 목적상 이유가 있다

| 항목 | SOL | 금융한걸음 | 이유 |
|---|---|---|---|
| 은행+계좌 입력 | 한 화면 | 단계 분리(`bank`→`account`) | 화면당 할 일이 하나여야 오답 지점을 특정할 수 있고, F8이 단계별로 다른 문구를 낼 수 있다 |
| 바텀시트/최근계좌/내계좌 | 있음 | 제외, 화면 하나로 단순화 | 1일 범위 밖. 화면 분리 자체는 SOL과 크게 다르지 않다는 근거로 삼는다 |
| 확인 화면 | 확인 모달 + 취소/이체하기 두 버튼 | `보내기` 하나 | 인증을 빼서 확인 화면이 "마지막으로 검토하는 자리" 역할만 하고, `MissionEngine.submit`에 뒤로가기 개념이 없다(F7) |

### 제외 — 이번 MVP에 넣지 않는다

| 항목 | 왜 빼나 |
|---|---|
| 메모 입력 | 송금을 익히는 것과 무관, 3명·1일 범위 밖 |
| ATM 등 다음 미션 이어가기 | 미션은 송금 1개다(SPEC 4.3), 이어갈 다음 미션이 없다 |
| 거래내역 상세 | 미션이 송금 1개라 거래내역 미션 자체가 제외 대상 |
| 공유 기능 | 앱 화면만 만든다, 가이드 사이트 자체의 껍데기 |
| 빠른 금액 버튼(1만/5만/10만/100만/전액) | 미션 목표가 5만원인데 `5만` 칩을 누르면 금액을 입력하는 연습 자체가 사라진다 |
| Click Here 방식의 정답 위치 직접 지시 | 이것이 F10(단계별 안내 배너, Won't)의 정체다. 우리는 스스로 찾아 누르는 것을 학습 목표로 삼는다 |

### 팀 결정 필요 — SPEC 12절로 넘어간 항목

| 항목 | 현재 SPEC 기준 | SPEC 12절 |
|---|---|---|
| 가상 은행명 | 현재 계획에 `국민은행`·`신한은행`·`농협은행`이 그대로 있음(실존 브랜드명, 특히 신한은행은 레퍼런스 은행 이름) — 바꾸는 쪽이 제안되었으나 미확정 | 12.3 |
| 비밀번호 단계 포함 여부 | **레퍼런스(쉬운이체)에는 없다** — 넣지 않는 쪽이 SPEC 작성자 의견이나 팀 결정 대기 | 12.4 |
| 목표 금액을 화면에 보여줄지 | 현재는 화면에 없음(옆 사람이 말로 알려주는 것을 전제) — 홈 화면에 미션 제목을 한 번만 띄우는 안(나)이 제안되었으나 미확정 | 12.5 |

이 세 항목은 SPEC에 이미 기록된 현재 값·제안 이상으로 이 문서가 임의로 확정하지 않는다.

## 여러 은행에서 공통적으로 참고할 요소

`[실사용 확인 필요]` — 신한 SOL 외 다른 은행 앱의 공통 패턴은 아직 조사 전이다. 특정 은행 하나가 아니라 여러 은행 앱의 송금 흐름에서 공통적으로 나타나는 패턴을 확인한 뒤 정리한다.

## 고령자 친화 UI 원칙

- 큰 글씨
- 큰 버튼
- 충분한 버튼 간격
- 한 화면에 과도한 정보 금지
- 실제 금융용어가 필요하면 쉬운 설명 병기 고려 (SPEC F2, Could)

## 금융한걸음 적용 원칙

- 신한 SOL뱅크 '돈 보내기'를 기본 정보 구조·단계 흐름·입력 방식의 주 레퍼런스로 삼되, 로고·명칭·브랜드 색상·이미지·아이콘·화면 디자인은 그대로 복제하지 않는다.
- 서비스 내부 은행은 특정 실제 은행이 아닌 **가상의 은행**으로 만든다.
- 필요하면 다른 은행의 공통적인 UX도 보완 참고한다.
- 교육용 가상 화면이며 실제 송금이 아니라는 사실이 화면에서 분명해야 한다.

## 구현 시 주의사항

- SPEC 11.2 기준, UI는 `screen/` 폴더(A 담당: `bank-ui.html`, `styles.css`)이며 `mission/`, `guide/` 폴더는 건드리지 않는다.
- SPEC 7절에 따라 F5(대형 키패드)는 Should다. Must 범위에서는 계좌번호·금액 입력에 기본 `<input>` 하나가 F4+F15 화면 안에 반드시 포함되어야 한다. SPEC 13.3 R2에 따라 실제 SOL 앱도 키패드가 유일한 입력 수단이라는 근거가 보강되었다.
- SPEC 5.2에 따라 마이크 권한은 보안 컨텍스트(localhost 또는 https)를 요구할 수 있다. `screen/bank-ui.html`을 `file://`로 직접 열면 마이크가 막힐 수 있으므로 UI 담당도 이 제약을 인지하고 시연 방식을 맞춰야 한다.
- SPEC 13.4에 따라 SOL 체험에는 오답·예외 화면이 존재하지 않는다. F8(오답 피드백)의 화면 쪽(흔들림·`showError`)은 참고할 실제 화면이 없으므로 A가 직접 설계해야 한다.
