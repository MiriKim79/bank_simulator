# UI/UX 레퍼런스

## 송금 기본 흐름

SPEC F4 기준 6단계: 이체 → 은행 선택 → 계좌번호 → 금액 → 확인 → 완료.

## 신한 SOL뱅크 참고 포인트

`[실사용 확인 필요]` — competitors.md의 "확인할 기능" 조사가 끝난 뒤, 참고할 만한 지점만 여기 옮긴다.

## 여러 은행에서 공통적으로 참고할 요소

`[실사용 확인 필요]` — 특정 은행 하나가 아니라 여러 은행 앱의 송금 흐름에서 공통적으로 나타나는 패턴을 확인한 뒤 정리한다.

## 고령자 친화 UI 원칙

- 큰 글씨
- 큰 버튼
- 충분한 버튼 간격
- 한 화면에 과도한 정보 금지
- 실제 금융용어가 필요하면 쉬운 설명 병기 고려 (SPEC F2, Could)

## 금융한걸음 적용 원칙

- 실제 특정 은행 화면을 그대로 복제하지 않는다.
- 여러 은행의 공통적인 송금 UX를 참고한 **가상의 은행**으로 만든다.
- 교육용 가상 화면이며 실제 송금이 아니라는 사실이 화면에서 분명해야 한다.

## 구현 시 주의사항

- SPEC 11.2 담당표 기준, UI 관련 파일(`bank-ui.html`, `styles.css`)은 A 담당이며 `mission-engine.js`, `ai-guide.js`는 건드리지 않는다.
- SPEC 7절에 따라 F5(대형 키패드)는 Should다. Must 범위에서는 계좌번호·금액 입력에 기본 `<input>` 하나가 F4 화면 안에 반드시 포함되어야 한다.
- SPEC 5.2에 따라 마이크 권한은 보안 컨텍스트(localhost 또는 https)를 요구할 수 있다. `file://`로 직접 열면 마이크가 막힐 수 있으므로 UI 담당도 이 제약을 인지하고 시연 방식을 맞춰야 한다.
