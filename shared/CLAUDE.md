# shared/ — 통합자 폴더 (담당 미리)

> 이 파일과 이 폴더는 **통합자만** 고친다.
> 팀원은 읽기만 한다. 여기 값을 바꿔야 하면 **카톡으로 통합자에게 요청**한다.

## 이 폴더가 하는 일

세 폴더가 공유하는 것만 둔다. **코드는 최소한으로.**

- `shared/CONTRACT.md` — 인터페이스 계약. 화면 이름 7개·`data-action` 값·DOM id·네 전역의 시그니처·`missions.json` 스키마·로드 순서
  - `plan.md` 의 Task S0 에서 **셋이 같이** 한 번 쓰고, 이후 변경은 셋이 합의한다
- `shared/llm-config.js` — `window.LLM_CONFIG`. **커밋하지 않는다**(`.gitignore`). 없으면 LLM 미연결로 동작하는 것이 정상
  - `.claude/settings.json` 에 `Read(shared/llm-config.js)` deny 가 걸려 있다. **Claude 는 이 파일을 읽지도 쓰지도 못한다** — 키는 사람이 직접 넣는다. `Read` deny 는 같은 경로의 `Edit` 까지 막으므로 의도된 설정이다

## 내 규칙 (통합자)

- **검증이 실패하면 고쳐주지 않는다.** 담당자를 카톡으로 부른다. 대신 고치면 다음 판에서 또 같은 실수가 온다
- 깨진 판을 배포하지 않는다. `OWNERS.md` 의 검증 3단계를 통과한 것만 배포한다
- 합칠 때마다 `SYNC-LOG.md` 한 줄 + `VERSION.txt` 판 번호를 올린다
- 코딩 몫을 적게 잡는다. **합치는 것이 통합자의 태스크다**
- `CONTRACT.md` 를 고쳤으면 `OWNERS.md` 의 「공통 약속」 표도 같이 고친다. 두 곳이 어긋나면 팀이 서로 다른 것을 믿는다

## 교환 규칙

`ZIP-PROTOCOL.md` 참조. 규칙 5개와 통합자 루프가 거기 있다.

## 경계

- 고쳐도 되는 곳: 전부 (통합자는 `deny` 가 거의 없다)
- 대신 **훅이 모든 수정을 기록한다** → `CHANGELOG-INBOX/`. 그게 통합 리포트가 된다
